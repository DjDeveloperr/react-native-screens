## NativeScript React Navigation Demo Verification

When verifying the NativeScript `react-native-screens` port with the UIKit demo:

- Launch the intended app deterministically before every stress run. Use bundle id `org.nativescript.uikit.demo`, then open the Expo dev-client URL:
  `org.nativescript.uikit.demo://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8082`.
- Keep a single SimDeck service mode per harness run. Do not mix isolated `simdeck/test` connections with CLI gestures/taps in the same stress flow; that caused workspace-local service conflicts and false failures.
- Scope native-AX searches to the target application root label `NativeScript UIKit Demo`, or to roots whose descendants contain known demo-only labels. This simulator may return background/stale roots for other installed apps, while Expo dev-client scenes can occasionally expose a generic `CoreNextApp` root label; global label searches can accidentally verify the wrong screen.
- When multiple visible application roots are present, treat the first non-empty root as foreground and reject later target-looking roots. A stale `NativeScript UIKit Demo` subtree behind a foreign foreground app can otherwise make `waitForReactNavRoot` pass while coordinate taps hit the wrong app, but empty lifecycle shells such as `Family` can appear before the real app and should not hide it.
- Prefer `simdeck processes` foreground bundle id as the hard guard before coordinate taps. AX root order is useful for labels, but process state is the authoritative way to reject app-switch contamination before sending a fixed point tap.
- Do not use SimDeck's generic `gesture swipe-from-left-edge` preset for React Navigation interactive-pop stress on this demo. If the app was opened from another app, that preset can hit iOS's status-bar previous-app breadcrumb and switch to the other app. Use an explicit horizontal edge drag through the content area, for example `simdeck swipe 6 454 330 454 --duration-ms 450 --post-delay-ms 250`, then assert the foreground root is still the demo.
- For cold relaunch stress, send the simulator Home before `simdeck launch` + `simdeck open-url`. Opening the dev-client URL while a foreign app is foreground can preserve the iOS previous-app breadcrumb and contaminate later coordinate taps.
- Reject implausible accessibility frames before tapping. If a queried button frame is larger than the visible control area, especially giant full-screen AX frames for modal dismiss buttons, fall back to known visible coordinates for the current route instead of tapping the frame center. Do not override plausible AX frames just because a screenshot appears visually offset; on 2026-06-12 the modal dismiss button's AX center was the actual tappable point, and a guessed lower visible coordinate caused false stress failures.
- Treat simulator AX visibility as a necessary observation, not UIKit transition/readiness proof. A button can be visible and stable in AX while UIKit is still finishing presentation or while NativeScript's detached RN touch host has a stale window origin. Verify gesture-back and modal-dismiss-after-gesture with focused unit regressions plus deterministic dev-client launch and compact first-tap/mixed SimDeck stress; do not close from screenshots or AX trees alone.
- Keep NativeScript host idempotence lifecycle-aware. `SafeAreaView` and screen content wrappers may keep identical frames while UIKit moves them between windows/presentation containers or a safe-area provider changes. Even when the frame is unchanged, refresh the relevant detached children/touch host on `didMoveToWindow`, provider notifications, content-wrapper frame signals, and modal presentation layout.
- Do not re-debug an already-root-caused simulator symptom when the active ask is source parity. First clean the mechanical port, comments, deviation inventory, and focused source tests; use simulator stress only as the verification gate after the parity work is coherent. If simulator state becomes flaky, shut down existing sims and verify on a fresh iOS 26.5 iPhone 17 simulator instead of layering more code changes onto stale AX/app lifecycle evidence.
- Treat fixed coordinate fallbacks as conditional, not authoritative. Before tapping a cached route coordinate, query the point label and ensure it still matches the intended visible control; otherwise use the current element center when its frame is plausible, or fail loudly. On 2026-06-12, a stale `Push React Navigation detail` fallback coordinate hit the demo's interactive-pop route after prior stress loops.
- Keep low-level raw `touch` gestures scoped to stable route buttons. Header chrome and transient UIKit menu/popover actions should use normal `simdeck tap`; raw touch against iOS 26 header/menu chrome intermittently terminated the harness process even though the app path worked with `tap`.
- Treat fallback screens such as `Hello, NativeScript`, `Animation Ready`, or unrelated CoreNext apps as launch/bootstrap failures, not navigation-port evidence. Relaunch the target bundle id and reopen the dev-client URL before continuing.
- If the correct bundle opens to a blank tab shell after source changes, terminate `org.nativescript.uikit.demo` before launching and opening the dev-client URL again. Reopening the URL into a stale dev-client scene can leave UIKit chrome alive while the React surface is not rendered.
- Remove temporary `[NS_*_DEBUG]` diagnostics before closing work. Verify with `rg -n "NS_MODAL_DEBUG|NS_STACK_DEBUG"` across the port, runtime, and demo harness.
- If first-tap modal stress fails while the screenshot/current tree is already back on the root route, check whether the failure artifact is a childless `NativeScript UIKit Demo` AX root. On 2026-06-12 artifacts `1781309305082-*`, `1781309371201-*`, and `1781309449085-*` were harness-only: modal `onPress` fired, and replacing `simdeck/test` tree/screenshot reads in `scripts/stress-react-nav-first-tap.js` with CLI `simdeck describe`/`screenshot` made modal-only and mixed stress pass. Keep the harness on one SimDeck access path.
- After `bob build`, run the full unit suite with generated `lib/` still present. Jest must ignore `<rootDir>/lib/`; otherwise Bob's generated `.test.js` files are discovered and source-parity tests that read sibling `.tsx` files fail for the wrong reason.
- Keep helper declarations above NativeScript worklets that capture them, especially worklets invoked from ObjC-exposed subclass methods like `didAddSubview:`. A helper declared later in the file can bundle as `undefined` in the UI runtime even when Jest/typecheck pass; verify with a real simulator relaunch after adding new native callback paths.
- Keep tabs lifecycle source-parity driven: `RNSTabsScreen` `onWillAppear`, `onDidAppear`, `onWillDisappear`, and `onDidDisappear` belong to `UIViewController` appearance selectors, not React mount/dispose. Store the NativeScript event context on the controller as the TS equivalent of upstream's `RNSTabsScreenEventEmitter`.
- Treat the NativeScript tabs host mount view tagged `TABS_MOUNT_VIEW_TAG` as a hidden staging area only. It is the TS equivalent of upstream Fabric `_reactSubviews`, not UIKit's visible tab content container; selected tab controller views must be owned by `UITabBarController` or the local fallback below the tab bar.
- Keep UIKit log sweeps separate from functional tap stress. Compare suspicious warnings against the upstream/native demo before changing port code. On 2026-06-12, upstream `react-native-screens` and the NativeScript port both logged the iOS 26 `UIScrollView does not support multiple observers...` assertion during modal/header stress, so that warning is baseline behavior, not a NativeScript regression.
- The NativeScript-only `Unbalanced calls to begin/end appearance transitions` warning was a generic runtime containment-order bug, not a screens-specific bug. `NativeScriptUIView` used to insert the hosted view first, then call `addChildViewController`, and compensate with manual `beginAppearanceTransition`/`endAppearanceTransition`. UIKit expects the source-parity order used by upstream `RNSScreenStack`: add child controller, insert hosted view, then `didMoveToParentViewController`. The generic runtime fix temporarily removes a hosted view that contains the controller view, attaches the controller, reinserts the hosted view, then calls `didMove`; manual appearance forwarding remains only as fallback when the host cannot reorder the visible view.
- Do not recycle nested `UINavigationController` children from `RNSScreen.viewDidDisappear`. That eager cleanup crashed the demo during the custom-header route. The safer source-parity port is `RNSScreenStackView.prepareForRecycle` on the stack owner's dispose; earlier teardown needs a runtime/containment-level fix, not a screen lifecycle shortcut.
- Do not switch `NativeScriptStackController` to `attachController={false}` and manually attach the stack `UINavigationController` from the TS wrapper view. That experiment restored upstream-looking attach order locally but broke modal-with-header content and repeatedly crashed from ObjC-exposed worklet capture order. The proper fix is the generic `NativeScriptUIView` containment-order behavior above.
- `RNSScrollViewMarker` is now a NativeScript `defineUIKitContainer`, not a Fabric native fallback. Keep its child lookup direct like upstream, but ignore NativeScriptUIView's hidden touch sentinel before resolving the direct `UIScrollView` / `RCTScrollViewComponentView.scrollView`; that sentinel is runtime plumbing, not a React child.
- iOS 26 `RNSTabsBottomAccessory` / `RNSTabsBottomAccessoryContent` are now NativeScript UIKit containers. Keep the host-owned `UITabAccessory` install path in `NativeScriptTabsHost`, with both regular/inline content trees mounted and layer-opacity switched from `traitCollection.tabAccessoryEnvironment`. The one known mechanical deviation is shadow-state feedback: upstream writes the native wrapper frame into Fabric C++ state, while the TS port records the frame and refreshes the generic NativeScript UIKit host because there is no TypeScript-visible shadow-state handle yet.
- Gamma `StackHost` / `StackScreen` iOS now route through `NativeScriptGammaStack.ios.tsx`. Keep the port source-shaped like upstream: a `UINavigationController` host, `UIViewController` screen wrappers, queued attached/detached activity-mode push/pop operations, and screen lifecycle events from appearance selectors. The current explicit deviation is scheduling only: upstream flushes via `RCTMountingTransactionObserving`, while the TS port coalesces the same ordered queue at the end of NativeScript host/screen callbacks.
- Gamma `StackHeaderConfig` / `StackHeaderItem` / `StackHeaderItemSpacer` iOS now route through `NativeScriptGammaStack.ios.tsx`. Keep them as NativeScript UIKit containers that build the same `UINavigationItem` data as upstream `RNSStackNavigationItemCoordinator`: title/titleView, iOS 26 large-title adjunct fields, left/right animated `UIBarButtonItem` arrays, fixed/flexible spacers, and nav-bar hidden state. The staging `UIView` is runtime plumbing only: React needs a hidden parent before UIKit wraps/moves custom header item views into bar items, whereas upstream receives children through Fabric component-view mount callbacks.
- Gamma `SplitHost` / `SplitScreen` iOS now route through `NativeScriptSplit.ios.tsx`. Keep the shape aligned with upstream Swift/ObjC: `UISplitViewController` host, `UINavigationController` wrappers per column, `UIViewController` screen columns, UIKit `show(column)` command support, appearance prop mapping through `UISplitViewController`, and screen lifecycle events from view-controller appearance selectors. The documented deviations are shadow-state/origin feedback and device-orientation enforcement: upstream mutates Fabric shadow state and calls `RNSScreenWindowTraits.enforceDesiredDeviceOrientation`, while the TS port refreshes the generic NativeScript host view and stores orientation because those native helpers are not exposed as generic NativeScript runtime APIs yet.
